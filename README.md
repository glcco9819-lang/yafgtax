# سامانه مدیریت دفتر حسابداری (YFGTAXES)

سامانه مدیریت عملیات دفاتر حسابداری - کنترل تسک، گزارش کار، تأیید مدیر و ارزیابی پرسنل

## ⚙️ معماری

- **Frontend**: Next.js 16 + TypeScript + Tailwind CSS + shadcn/ui
- **Backend**: Next.js API Routes (RESTful)
- **Database**: SQLite (توسعه) / PostgreSQL (تولید) با Prisma ORM
- **Authentication**: Custom JWT-based session

## 📋 قابلیت‌های نسخه MVP

### ۱. مدیریت کاربران و دسترسی
- ورود با نام کاربری و رمز عبور
- نقش‌ها: employee (کارمند)، supervisor (سرپرست)، ceo (مدیرعامل)، admin (مدیر سیستم)
- کنترل دسترسی به شرکت‌ها (RBAC)

### ۲. مدیریت شرکت‌ها
- تعریف شرکت (تا ۵۰۰۰ شرکت)
- مشخص کردن نرم‌افزار حسابداری هر شرکت (همکاران، سپیدار، هلو، تندیس، ترکیبی)
- غیرفعال‌سازی شرکت

### ۳. مدیریت تسک‌ها
- ایجاد تسک با عنوان، توضیحات، مهلت، اولویت (low/medium/high/critical) و وزن (1-10)
- تخصیص تسک به یک یا چند کارمند (اصلی یا همکار)
- چک‌لیست مراحل تسک
- ۱۰ وضعیت برای تسک: draft، assigned، in_progress، submitted، reconciling، needs_review، returned، approved، approved_with_exception، rejected، cancelled

### ۴. گزارش کار و بارگذاری فایل
- ثبت گزارش کار با بازه زمانی (از تا)
- بارگذاری فایل اکسل (با اعتبارسنجی هش SHA-256 برای جلوگیری از ثبت تکراری)
- فایل در سرور محلی دفتر ذخیره می‌شود (در نسخه MVP در /tmp)

### ۵. فایل مرجع مدیر (اختیاری)
- بارگذاری اختیاری فایل مرجع برای راستی‌آزمایی
- نسخه‌بندی خودکار (هر بارگذاری یک نسخه جدید)
- چندین تسک می‌توانند از یک نسخه مرجع استفاده کنند
- نسخه‌های قبلی برای ممیزی حفظ می‌شوند

### ۶. تصمیم مدیر (۴ نوع)
- **تأیید عادی**: کار بدون اشکال پذیرفته می‌شود
- **تأیید با ارفاق**: کار با اختلاف قابل قبول پذیرفته می‌شود (با ذکر دلیل ارفاق)
- **بازگشت برای اصلاح**: کار به کارمند برمی‌گردد (دلیل قابل مشاهده الزامی)
- **رد نهایی**: کار قابل قبول نیست (دلیل الزامی)

### ۷. نمره ۰-۱۰۰ مستقل
- مدیر می‌تواند به هر تسک نمره ۰ تا ۱۰۰ بدهد
- نمره مستقل از نوع تصمیم (تأیید کار لزوماً به معنی نمره ۱۰۰ نیست)
- نمره در ارزیابی ماهانه کارمند لحاظ می‌شود

### ۸. یادداشت دو سطحی
- یادداشت قابل مشاهده برای کارمند (نمایش در پنل کارمند)
- یادداشت محرمانه مدیر (فقط مدیر می‌بیند، کارمند نمی‌بیند)

### ۹. حضور و غیاب
- ثبت ورود روزانه (check-in)
- ثبت خروج (check-out)
- جلوگیری از ثبت تکراری در همان روز

### ۱۰. درخواست مرخصی
- ثبت درخواست مرخصی با نوع (شخصی، بیماری، اضطراری، استحقاقی)
- گردش تأیید: سرپرست یا مدیرعامل
- اطلاع‌رسانی خودکار به مدیران

### ۱۱. اعلان‌ها
- اعلان تخصیص تسک
- اعلان ثبت گزارش کار
- اعلان تصمیم مدیر
- اعلان درخواست مرخصی

### ۱۲. لاگ فعالیت (Audit Log)
- ثبت تمام رویدادهای مهم (ایجاد، ویرایش، حذف، تأیید، رد)
- هر رویداد شامل: کاربر، زمان، نوع، شناسه شیء، حالت قبلی و جدید
- قابل جست‌و‌جو با correlation_id

## 🚀 راه‌اندازی

### پیش‌نیازها
- Node.js 18+ یا Bun
- npm یا bun package manager

### مراحل

```bash
# 1. نصب وابستگی‌ها
bun install  # یا npm install

# 2. تنظیم متغیرهای محیطی
cp .env.example .env
# محتوای .env:
# DATABASE_URL="file:./db/custom.db"
# JWT_SECRET="your-secret-key-at-least-32-chars"

# 3. ساخت دیتابیس
bun run db:push

# 4. اجرای برنامه در حالت توسعه
bun run dev
# برنامه روی http://localhost:3000 اجرا می‌شود

# 5. ساخت داده‌های اولیه (اولین بار)
# از صفحه ورود، روی دکمه "ساخت داده‌های اولیه (seed)" کلیک کنید
# یا API را فراخوانی کنید:
curl -X POST http://localhost:3000/api/seed
```

    ├── auth.ts                  # Authentication helpers

## 🔐 امنیت

- رمزهای عبور با SHA-256 + salt ذخیره می‌شوند (در تولید از bcrypt استفاده کنید)
- کنترل دسترسی در سطح API (RBAC)
- جدول audit_events برای تاریخچه کامل (Append-only)
- Tokens با مدت انقضای ۲۴ ساعت

## 📊 مدل داده

۱۸ مدل اصلی در PostgreSQL/SQLite:
- User, Company, UserCompanyAccess, FiscalPeriod
- Task, TaskAssignment, TaskChecklistItem, TaskReferenceBinding
- WorkSubmission, ManagerDecision, ReferenceVersion
- LeaveRequest, AttendanceRecord, Notification
- AuditEvent, PerformanceScore
