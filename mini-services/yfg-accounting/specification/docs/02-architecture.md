# ۲. معماری پیشنهادی

## رویکرد
معماری وب‌محور، ماژولار و Local-first. نسخه اول در شبکه دفتر اجرا می‌شود؛ دسترسی بیرون دفتر از VPN امن انجام می‌شود. هر نرم‌افزار حسابداری در آینده می‌تواند connector جداگانه داشته باشد.

## فناوری پیشنهادی
- UI: React/Next.js + TypeScript، فارسی و RTL.
- Backend: Python + FastAPI.
- Database: PostgreSQL.
- Excel: openpyxl؛ pandas در صورت نیاز به پردازش جدولی.
- فایل‌ها: ذخیره‌ساز محلی غیرقابل دسترسی مستقیم از وب.
- Worker: job table و پردازش پس‌زمینه برای ورود فایل و تطبیق.
- استقرار: Docker Compose یا سرویس‌های مدیریت‌شده روی سرور دفتر.

## نمای منطقی
```text
مرورگر مدیر/کارمند
       | HTTPS
رابط وب RTL
       | API
FastAPI ---- احراز هویت/مجوز
  |       |        |
Postgres فایل‌ها  Worker
metadata  محلی    Excel -> Normalize -> Reconcile
  |
Audit / Reports / Notifications
```

## ماژول‌ها
1. احراز هویت و مجوزها
2. شرکت‌ها و دوره‌های مالی
3. مدیریت تسک و تاریخچه
4. مرجع و نسخه‌های آن
5. ارسال کار و فایل‌ها
6. ورود و نرمال‌سازی Excel
7. موتور تطبیق و گزارش اختلاف
8. تصمیم مدیر و یادداشت‌ها
9. گزارش عملکرد
10. ممیزی و اعلان

## اصول معماری
- فایل اصلی و نتایج هر اجرا immutable باشند.
- هر اجرا `algorithm_version` و شناسه ورودی‌ها را ثبت کند.
- داده خام حسابداری از شبکه عمومی بیرون نرود.
- فایل Excel غیرقابل اعتماد فرض شود؛ macro اجرا نشود و پردازش محدود باشد.
- دسترسی یادداشت محرمانه در لایه API/service کنترل شود، نه فقط در رابط.
